# Task API

A small FastAPI service exposing CRUD endpoints over a **SQLite** database of tasks.

The app is organised in layers:

- [models/task.py](models/task.py) — the `Task` SQLModel (also the request/response schema)
- [repositories/task_repository.py](repositories/task_repository.py) — all database access
- [services/task_services.py](services/task_services.py) — business logic (filtering, stats)
- [routes/task_routes.py](routes/task_routes.py) — HTTP endpoints
- [database.py](database.py) — the SQLModel engine
- [main.py](main.py) — app wiring, table creation, and seed data

## Why SQLite

SQLite was chosen because it fits this project's needs without extra moving parts:

- **Zero setup** — it ships with Python (the `sqlite3` module) and needs no separate
  server, credentials, or network config. Perfect for a small single-service API.
- **Single file** — the whole database is one `tasks.db` file, so it is trivial to
  create, back up, delete, or inspect.
- **Good enough for the workload** — a task list is low-concurrency, low-volume data;
  SQLite handles this comfortably.
- **Easy migration path** — access goes through SQLModel/SQLAlchemy, so moving to
  PostgreSQL later is a one-line change to the connection URL in [database.py](database.py).

## Where the database is stored

The database is a single file, `tasks.db`, in the project root
([first_assessment/tasks.db](tasks.db)). It is created automatically on first run.

The location comes from the connection URL in [database.py](database.py):

```python
Database_URL = "sqlite:///./tasks.db"   # ./ = relative to the working directory
```

You may also see a `tasks.db-journal` file next to it while the app is running — that
is SQLite's rollback journal and is safe to ignore.

## Install & run

From `first_assessment/`, with the bundled virtualenv:

```powershell
flyrank\Scripts\Activate.ps1
fastapi dev main.py
```

The API is then at `http://127.0.0.1:8000`. On the first run `main.py` creates the
`tasks` table (if missing) and seeds three example tasks. Interactive docs are
generated by FastAPI at `/docs` (Swagger UI) and `/redoc`.

If you'd rather set up your own environment:

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install "fastapi[standard]" sqlmodel
fastapi dev main.py
```

## Endpoints

| Method | Path          | Success        | Description                            |
| ------ | ------------- | -------------- | -------------------------------------- |
| GET    | `/`           | 200            | API name, version, and endpoint list   |
| GET    | `/health`     | 200            | Liveness check — `{"status": "ok"}`    |
| GET    | `/tasks`      | 200            | All tasks, optionally filtered         |
| GET    | `/tasks/{id}` | 200 / 404      | One task by id                         |
| POST   | `/tasks`      | 201 / 400      | Create a task from `{"title", "done"}` |
| PUT    | `/tasks/{id}` | 200 / 400/ 404 | Replace a task's title and done flag   |
| DELETE | `/tasks/{id}` | 204 / 404      | Remove a task                          |
| GET    | `/stats`      | 200            | Counts — `{"total", "done", "open"}`   |

A task is `{"id": int, "title": str, "done": bool}`. `id` is assigned by the database;
request bodies only carry `title` (required) and `done` (defaults to `false`).

Errors come back as `{"error": "..."}`.

### Filtering `/tasks`

`GET /tasks` accepts two optional query parameters, applied to the rows loaded from
the database:

| Param    | Type   | Effect                                            |
| -------- | ------ | ------------------------------------------------- |
| `done`   | bool   | Only tasks whose `done` matches                   |
| `search` | string | Only tasks whose title contains it, ignoring case |

```console
$ curl -s "http://127.0.0.1:8000/tasks?done=false"
[{"id":1,"title":"Task 1","done":false},{"id":3,"title":"Task 3","done":false}]

$ curl -s "http://127.0.0.1:8000/tasks?search=task%202"
[{"id":2,"title":"Task 2","done":true}]
```

Both filters combine — `done` is applied first, then `search` narrows the result
further. Passing a non-boolean `done` (e.g. `?done=yes please`) is a 422.

## Example request

```console
$ curl -i -X POST http://127.0.0.1:8000/tasks \
    -H "Content-Type: application/json" \
    -d '{"title":"Write README"}'
HTTP/1.1 201 Created
server: uvicorn
content-type: application/json

{"id":4,"title":"Write README","done":false}
```

And a miss:

```console
$ curl -i http://127.0.0.1:8000/tasks/99
HTTP/1.1 404 Not Found
server: uvicorn
content-type: application/json

{"error":"Task 99 not found"}
```

## Example SQL executed

`create_engine(..., echo=True)` in [database.py](database.py) logs every statement
SQLModel runs. For example, creating a task issues:

```sql
INSERT INTO tasks (title, done) VALUES ('Write README', 0);
```

and `GET /tasks` runs:

```sql
SELECT tasks.id, tasks.title, tasks.done
FROM tasks;
```

The `tasks` table itself is created by [main.py](main.py) with:

```sql
CREATE TABLE IF NOT EXISTS tasks (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    title TEXT NOT NULL,
    done BOOLEAN NOT NULL DEFAULT 0
);
```
